## Theory

A **context-free grammar (CFG)** is a formal system that describes a context-free language using production rules. A grammar G is defined as a 4-tuple G = (V_N, V_T, P, S), where V_N is the set of non-terminals, V_T is the set of terminals, P is the set of productions, and S is the start symbol.

A grammar is in **Chomsky Normal Form (CNF)** if every production has exactly one of two forms:
- **A → BC** — one non-terminal produces exactly two non-terminals
- **A → a** — one non-terminal produces exactly one terminal

where A, B, C ∈ V_N and a ∈ V_T. No other form is permitted — no ε-productions, no unit rules, no mixed or longer right-hand sides.

Every context-free language (except those containing ε) has an equivalent grammar in CNF. Converting to CNF is useful because it gives productions a uniform, predictable shape, which simplifies parsing algorithms such as the CYK algorithm.

Converting an arbitrary CFG to CNF requires five normalization steps applied in order. Each step eliminates one class of rule that violates CNF constraints, while preserving the language generated by the grammar.

### Step 1 — Eliminate ε-Productions

An ε-production is any rule of the form A → ε. CNF does not permit empty productions. Simply deleting them would change the language, because other rules may rely on A being able to disappear. Instead, for every production containing a nullable symbol, a new version of that production is added with that symbol omitted.

**Algorithm:**
1. Find all nullable symbols — those that can derive ε directly or through a chain.
2. For each production containing a nullable symbol, generate all combinations with that symbol present or absent.
3. Remove all ε-productions.

For Variant 3, `C → ε` makes C nullable. The affected production is `B → aC` and `B → AC`, producing new rules `B → a` and `B → A`.

```java
// find nullable symbols iteratively
Set<String> nullable = new LinkedHashSet<>();
for (Map.Entry<String, List<String>> e : productions.entrySet())
    if (e.getValue().contains("ε"))
        nullable.add(e.getKey());

// generate all subsets with nullable positions omitted
int subsets = 1 << nullablePos.size();
for (int mask = 1; mask < subsets; mask++) { ... }
```

### Step 2 — Eliminate Renamings

A **renaming** (unit production) is a rule of the form A → B, where both sides are single non-terminals. CNF does not allow this. The fix is to replace the rename with all productions of the target symbol.

**Algorithm:**
1. Find all unit productions A → B.
2. Replace A → B with every rule that B produces.
3. Repeat until no unit productions remain (handles chains like A → B → C).

For Variant 3, `S → A` is a renaming. It gets replaced with all of A's productions: `S → d`, `S → dS`, `S → aAdAB`.

```java
for (String rhs : e.getValue()) {
    if (isNonTerminal(rhs) && productions.containsKey(rhs)) {
        for (String sub : productions.get(rhs))
            newRHS.add(sub);   // copy target's productions
        newRHS.remove(rhs);    // remove the unit rule
    }
}
```

### Step 3 — Eliminate Inaccessible Symbols

An **inaccessible symbol** is one that can never be reached in any derivation starting from S. Such symbols and their productions can be safely removed without affecting the language.

**Algorithm:**  
BFS/reachability from the start symbol. Any symbol — terminal or non-terminal — that is never referenced in a reachable production is inaccessible.

For Variant 3, `E` is never referenced by S or any symbol reachable from S. It is removed along with its production `E → AS`.

```java
Set<String> accessible = new LinkedHashSet<>();
accessible.add(startSymbol);
// expand: for each accessible NT, mark everything in its RHS as accessible
for (String sym : splitRHS(rhs))
    accessible.add(sym);
// remove anything not reached
nonTerminals.retainAll(accessible);
productions.keySet().retainAll(nonTerminals);
```

---

### Step 4 — Eliminate Non-Productive Symbols

A **non-productive symbol** is a non-terminal that can never derive a string consisting entirely of terminals, no matter how many steps are taken. Such symbols and all rules referencing them are removed.

The formal definition is:

```
PROD(G)   = { A | A ∈ V_N, ∃ A ⟹ v, v ∈ V_T* }
NEPROD(G) = V_N \ PROD(G)
```

**Algorithm:**  
Start with the set of terminals (trivially productive). Iteratively mark a non-terminal as productive if every symbol in at least one of its right-hand sides is already known productive. Repeat until stable.

For Variant 3, after previous steps `C` has only `C → abC` which loops on itself — it can never bottom out. So `PROD(G) = {B, S, A}` and `NEPROD(G) = {C}`. C and all rules referencing it are removed.

```java
Set<String> productive = new LinkedHashSet<>(terminals);
for (String s : splitRHS(rhs))
    if (!productive.contains(s)) { allProd = false; break; }
if (allProd) productive.add(e.getKey());
```

### Step 5 — Convert to CNF

After the four cleanup steps, the grammar may still have rules that are too long (more than 2 symbols) or mix terminals and non-terminals. These are fixed in two passes:

**Pass 1 — Wrap terminals:** In any rule with more than one symbol, replace each terminal `a` with a new non-terminal `Xi` and add `Xi → a`.

**Pass 2 — Binarize:** Any rule A → B1 B2 B3 ... Bn with n > 2 is broken into a chain of binary rules using helper non-terminals `Yi`:
```
A  → B1 Y1
Y1 → B2 Y2
Y2 → B3 B4
```

```java
// Pass 1: replace terminals in long rules
if (terminals.contains(syms[i])) {
    String newNT = "X" + counter[0]++;
    terminalMap.put(t, newNT);
    cnfProds.put(newNT, List.of(t));
}

// Pass 2: binarize
private String binarize(String[] syms, ...) {
    if (syms.length == 2) return syms[0] + syms[1];
    String newNT = "Y" + counter[0]++;
    cnfProds.put(newNT, List.of(binarize(rest, ...)));
    return syms[0] + newNT;
}
```

## Conclusions

This laboratory work demonstrates how an arbitrary context-free grammar can be systematically transformed into Chomsky Normal Form through five ordered normalization steps.

The key design decisions were:

1. **Encapsulating each step as a separate method** in the `Grammar` class. This makes the pipeline easy to follow and test — each step can be verified independently by printing the grammar state after it runs.

2. **Iterative fixed-point algorithms** for steps 1, 2, and 4. Finding nullable symbols, resolving renaming chains, and marking productive symbols all require repeated passes until no further changes occur. Using a `changed` flag to drive the loop handles arbitrary chain depths without hardcoding assumptions about the grammar structure.

3. **Separating binarization from terminal wrapping** in Step 5. Handling them as two distinct passes avoids interference — terminals are replaced with NT proxies first, so binarization only ever sees non-terminals and can assume a clean input.

One challenge encountered was correctly parsing mixed RHS strings like `"aAdAB"` into individual symbols. Since non-terminals can be multi-character (e.g. `X1`, `Y3`), a simple character-by-character split is insufficient. The `splitRHS()` helper solves this by treating an uppercase letter followed by digits as a single symbol token.
